# VPN/Proxy Telegram-бот

Telegram-бот для продажи и управления подписками на доступ к прокси
(см. `../web-proxy/`) — по образцу ботов вроде Atlanta VPN: три кнопки
(«Личный кабинет», «Управление подписками», «Купить подписку»), реальная
оплата через Telegram и автоматическая выдача/отключение доступа.

Написан на [Telegraf](https://telegraf.js.org/) — единственная внешняя
зависимость.

## Как это работает целиком

1. Бот и `web-proxy` используют **один и тот же JSON-файл** как общее
   хранилище пользователей и подписок (`STORE_PATH` в боте =
   `SUBSCRIPTIONS_FILE` в прокси).
2. При первом обращении к боту (`/start` или любая кнопка) пользователю
   генерируются уникальные логин/пароль для прокси.
3. При успешной оплате бот продлевает подписку в этом файле.
4. `web-proxy` при каждой попытке подключения читает файл заново и
   проверяет логин/пароль **и** что подписка не истекла — то есть доступ
   реально включается и выключается по факту оплаты, без перезапуска
   сервисов.

```
┌─────────────┐        общий store.json        ┌────────────┐
│ telegram-bot│ ───── читает/пишет ───────────▶ │  web-proxy │
└─────────────┘                                  └────────────┘
      ▲                                                 ▲
      │ Telegram Bot API                                │ HTTP(S) / SOCKS5
      │                                                  │
   пользователь                                     пользователь
```

## Функциональность

- **👤 Личный кабинет** — статус подписки, дата окончания, логин/пароль
  и адреса прокси, готовая команда для проверки через curl.
- **📋 Управление подписками** — история всех подписок (активные/истёкшие),
  кнопка «Продлить/купить».
- **💳 Купить подписку** — выбор тарифа (1/3/6/12 месяцев) и оплата прямо
  в Telegram: `sendInvoice` → `pre_checkout_query` → `successful_payment`,
  после чего подписка продлевается автоматически (с накоплением остатка,
  если продлевали заранее).
- Оплата **Telegram Stars** работает из коробки — не нужен ни один внешний
  платёжный аккаунт. При необходимости принимать рубли/карты — подключите
  `PROVIDER_TOKEN` от @BotFather (ЮKassa и т.п.), бот переключится на RUB.
- `/grant <telegram_id> <planId>` — ручная выдача подписки администраторам
  (`ADMIN_IDS`), для поддержки и тестирования без реальной оплаты.
- HTTP API (см. ниже) для Android-приложения `../android-app/`: связка
  аккаунта через Telegram по одноразовому коду, личный кабинет, история
  подписок — без пароля, только через сам Telegram.

## HTTP API для приложения

Поднимается тем же процессом (`npm start`), порт задаётся `API_PORT`
(по умолчанию 3000). Разработан для Android-клиента в `../android-app/`,
но это обычный JSON HTTP API — можно дёргать чем угодно.

Связка аккаунта происходит **через сам Telegram**, без пароля в
приложении:

1. `POST /api/link/start` → `{ code, deepLink, expiresIn }`. `deepLink`
   вида `https://t.me/<bot>?start=link_<code>` — открывается в Telegram.
2. Пользователь жмёт Start в Telegram — бот распознаёт `link_<code>`
   в `/start` и привязывает код к своему Telegram ID.
3. Приложение поллит `GET /api/link/status?code=<code>` (валиден 10
   минут) до `{ valid: true, linked: true, sessionToken }`.
4. Дальше запросы идут с `Authorization: Bearer <sessionToken>`:
   - `GET /api/me` — профиль, статус подписки, логин/пароль/адреса прокси.
   - `GET /api/subscriptions` — история подписок.
   - `POST /api/logout` — отозвать токен (выход из приложения).
   - `GET /api/plans` — список тарифов с ценами в текущей валюте
     (Stars или RUB) — без авторизации, для экрана «Купить подписку».

Оплата тарифа всё равно происходит **в Telegram** (Stars/Payments API
доступны только там) — приложение открывает
`https://t.me/<bot>?start=buy_<planId>`, бот сразу присылает счёт.
После оплаты приложение просто перезапрашивает `/api/me`.

## Быстрый старт

1. Создайте бота через [@BotFather](https://t.me/BotFather), получите
   `BOT_TOKEN`.
2. (Опционально) `/mybots` → ваш бот → Payments → подключите провайдера,
   получите `PROVIDER_TOKEN`. Без этого шага работает оплата Stars.
3. Установите зависимости и настройте окружение:

   ```bash
   npm install
   cp .env.example .env
   # впишите BOT_TOKEN, PROXY_HOST (адрес вашего web-proxy) и т.д.
   ```

4. Запустите (переменные из `.env` нужно экспортировать в окружение —
   например, `set -a && source .env && set +a`, либо через systemd, см.
   ниже):

   ```bash
   npm start
   ```

5. Запустите `web-proxy` рядом, указав тот же файл хранилища:

   ```bash
   cd ../web-proxy
   SUBSCRIPTIONS_FILE=/путь/к/store.json PROXY_HTTP_PORT=8080 PROXY_SOCKS_PORT=1080 node index.js
   ```

## Конфигурация (переменные окружения)

| Переменная          | Назначение                                                   | По умолчанию |
|----------------------|---------------------------------------------------------------|--------------|
| `BOT_TOKEN`          | токен бота от @BotFather (обязательно)                         | —            |
| `PROVIDER_TOKEN`     | токен платёжного провайдера — включает оплату в RUB            | не задан (оплата в Stars) |
| `STORE_PATH`         | путь к общему JSON-хранилищу                                    | `./data/store.json` |
| `PROXY_HOST`         | адрес web-proxy, показывается пользователю                     | `127.0.0.1`  |
| `PROXY_HTTP_PORT`    | порт HTTP(S)-прокси, показывается пользователю                 | `8080`       |
| `PROXY_SOCKS_PORT`   | порт SOCKS5-прокси, показывается пользователю                  | `1080`       |
| `ADMIN_IDS`          | Telegram ID через запятую, у кого доступна `/grant`             | —            |
| `SUPPORT_USERNAME`   | юзернейм поддержки (не используется автоматически, для справки) | —            |
| `API_HOST`/`API_PORT`| адрес и порт HTTP API для приложения                            | `0.0.0.0:3000` |
| `BOT_USERNAME`       | юзернейм бота без `@` (для deep link'ов из API)                 | определяется автоматически при старте |

Тарифы (длительность/цена) заданы в `lib/plans.js` — поправьте под себя.

## Развёртывание

Пример systemd-юнита — `vpn-bot.service.example`:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now vpn-bot
```

`data/store.json` не коммитится (реальные пользователи и пароли) —
создаётся автоматически при первом запуске.

## Что нужно проверить самостоятельно

Я протестировал всю логику, которая не требует живого Telegram-токена:
конструирование бота, генерацию подписок/логинов/паролей и полный цикл
`web-proxy` ↔ `store.json` (выдача доступа при активной подписке,
блокировка при истёкшей). Сам процесс оплаты в Telegram (`sendInvoice` →
`successful_payment`) может проверить только реальный пользователь с
реальным ботом — после того как вы впишете свой `BOT_TOKEN` и запустите
бота, пройдите оплату один раз тестовым платежом (Stars — можно реальными
на минимальном тарифе, провайдеры вроде ЮKassa обычно дают тестовый режим).
