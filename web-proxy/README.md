# web-proxy — личный HTTP(S) + SOCKS5 прокси

Прокси-сервер для повседневного использования (браузер, мессенджеры,
консольные утилиты) с обязательной авторизацией по логину и паролю.
Написан на Node.js без внешних зависимостей: одним процессом поднимает
и HTTP(S)-прокси, и SOCKS5.

- **HTTP(S)**: обычные HTTP-запросы форвардятся напрямую, HTTPS — через
  `CONNECT`-туннель (браузер видит обычный HTTP-прокси).
- **SOCKS5**: полная поддержка `CONNECT` с обязательной авторизацией
  username/password (RFC 1929) — подходит для Telegram, торрент-клиентов,
  SSH и любого ПО, поддерживающего SOCKS5.

Оба сервера **не пропускают ни одного запроса без верных логина и
пароля** — открытым прокси это не станет.

## Запуск

Требуется только Node.js (16+).

```bash
cp config.example.json config.json
# впишите в config.json своих пользователей и порты
node index.js
# или
npm start
```

Быстрый вариант для одного пользователя — без файла конфигурации:

```bash
PROXY_USER=myuser PROXY_PASSWORD='strong-password' node index.js
```

## Конфигурация

`config.json` (см. `config.example.json`):

```json
{
  "listenHost": "0.0.0.0",
  "httpPort": 8080,
  "socksPort": 1080,
  "idleTimeoutMs": 120000,
  "users": {
    "myuser": "strong-password"
  }
}
```

Переменные окружения (приоритет выше, чем у `config.json`):

| Переменная               | Назначение                                  | По умолчанию |
|--------------------------|----------------------------------------------|--------------|
| `PROXY_LISTEN_HOST`      | адрес, на котором слушают оба сервера         | `0.0.0.0`    |
| `PROXY_HTTP_PORT`        | порт HTTP(S)-прокси                           | `8080`       |
| `PROXY_SOCKS_PORT`       | порт SOCKS5-прокси                            | `1080`       |
| `PROXY_IDLE_TIMEOUT_MS`  | таймаут неактивного соединения, мс            | `120000`     |
| `PROXY_USER`/`PROXY_PASSWORD` | добавить одного пользователя без config.json | — |
| `PROXY_CONFIG`           | путь к альтернативному config.json            | `./config.json` |

`config.json` не коммитится в репозиторий (в нём пароли) — используйте
`config.example.json` как шаблон.

## Использование

**Браузер / приложения с HTTP-прокси:** укажите адрес сервера и
`httpPort` как HTTP- и HTTPS-прокси, при первом запросе появится окно
ввода логина/пароля (Basic-авторизация на уровне прокси).

**curl:**

```bash
curl -x http://myuser:strong-password@SERVER_IP:8080 https://example.com
```

**SOCKS5 (curl, ssh, Telegram и т.д.):**

```bash
curl --socks5 myuser:strong-password@SERVER_IP:1080 https://example.com
```

## Развёртывание и безопасность

- Используйте длинный случайный пароль на пользователя.
- Ограничьте доступ фаерволом до нужных IP, если знаете, откуда будете
  подключаться, либо хотя бы включите логирование и следите за трафиком.
- **Важно:** сами протоколы HTTP-proxy Basic-auth и SOCKS5 RFC 1929 не
  шифруют канал между клиентом и прокси — пароль и заголовок авторизации
  передаются в открытом виде на этом участке (трафик до конечного
  `https://`-сайта при этом всё равно зашифрован end-to-end, это отдельный
  уровень). Если прокси используется из недоверенных сетей (кафе,
  публичный Wi-Fi), заверните соединение до сервера в дополнительный
  туннель — например, SSH (`ssh -L 8080:localhost:8080 user@server`) или
  WireGuard — либо ограничьте доступ по IP через фаервол.
- Пример systemd-юнита — `web-proxy.service.example`. Скопируйте в
  `/etc/systemd/system/web-proxy.service`, поправьте пути/`User`/логин-пароль:

  ```bash
  sudo systemctl daemon-reload
  sudo systemctl enable --now web-proxy
  ```
