# Harribel Proxy — UDP-прокси для игрового сервера

Простой UDP-прокси на Node.js без внешних зависимостей. Стоит перед
реальным SA-MP/open.mp сервером: игроки подключаются к прокси, а он
прозрачно пересылает пакеты на настоящий сервер и обратно. Настоящий
IP-адрес сервера при этом не виден игрокам — это снижает риск DDoS-атак
на сам игровой сервер (одна из самых частых проблем у публичных
SA-MP-проектов).

Прокси не разбирает протокол RakNet/SA-MP — он просто пересылает байты,
поэтому совместим и с классическим SA-MP 0.3.7, и с open.mp.

## Как это работает

- Прокси слушает публичный UDP-порт (`listenPort`).
- На каждого нового клиента заводится отдельный "исходящий" сокет,
  через который пакеты идут к реальному серверу — так ответы сервера
  однозначно сопоставляются с нужным игроком.
- Если от клиента долго (`idleTimeoutMs`) нет пакетов, его сокет
  закрывается, чтобы не копить файловые дескрипторы.
- Есть простой лимит одновременных клиентов (`maxClients`) как базовая
  защита от исчерпания ресурсов.

## Запуск

Требуется только Node.js (16+), внешние npm-пакеты не нужны.

```bash
cp config.example.json config.json
# отредактируйте config.json: укажите реальный адрес игрового сервера
node index.js
# или
npm start
```

## Конфигурация

Настройки читаются из `config.json` (см. `config.example.json`), а
переменные окружения имеют более высокий приоритет:

| Переменная                | Назначение                                   | По умолчанию |
|---------------------------|-----------------------------------------------|--------------|
| `PROXY_LISTEN_HOST`       | адрес, на котором слушает прокси              | `0.0.0.0`    |
| `PROXY_LISTEN_PORT`       | публичный порт для игроков                    | `7777`       |
| `PROXY_TARGET_HOST`       | реальный IP/хост игрового сервера             | `127.0.0.1`  |
| `PROXY_TARGET_PORT`       | реальный порт игрового сервера (`server.cfg`) | `7777`       |
| `PROXY_IDLE_TIMEOUT_MS`   | таймаут неактивного клиента, мс               | `60000`      |
| `PROXY_MAX_CLIENTS`       | лимит одновременных клиентов                  | `500`        |
| `PROXY_CONFIG`            | путь к альтернативному config.json            | `./config.json` |

`config.json` не коммитится в репозиторий (в нём может быть реальный
IP сервера) — используйте `config.example.json` как шаблон.

## Развёртывание

Рекомендуемая схема: прокси и реальный игровой сервер — на разных
машинах (или хотя бы на разных портах одной машины). Игрокам, на сайте
и в списках серверов должен быть указан адрес **прокси** (публичный
IP), а не реального сервера — иначе смысл прокси теряется. В
конфигурации самого игрового сервера (`server.cfg`/`config.json`
SA-MP/open.mp: `weburl`, `hostname`) и на сайте проекта укажите именно
адрес прокси.

Пример systemd-юнита — `harribel-proxy.service.example`. Скопируйте его
в `/etc/systemd/system/harribel-proxy.service`, поправьте пути/`User` и
включите:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now harribel-proxy
```

## Ограничения

Это прокси уровня пакетов (L4/L7-agnostic UDP forwarding), а не полноценная
anti-DDoS система: он скрывает реальный IP и режет число одновременных
"клиентов", но не фильтрует flood по содержимому пакетов и не заменяет
защиту на уровне провайдера/фаервола для по-настоящему крупных атак.
